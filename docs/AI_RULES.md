# AI Правила и Архитектурные Решения

Этот файл содержит зафиксированные архитектурные решения и правила, принятые в ходе разработки. Используется для контекста AI-ассистента.

## 1. Data Ingestion & File Upload
* **ПРАВИЛО:** Файлы в систему загружаются ТОЛЬКО через пользовательский интерфейс (Chainlit Admin UI) и обрабатываются через FastAPI бэкенд.
* **ПРАВИЛО:** Отдельный микросервис `sync-agent` с `watchdog` **НЕ ИСПОЛЬЗУЕТСЯ**.
* **ПРАВИЛО:** Пайплайн векторизации (parsing -> chunking -> embedding -> qdrant upsert) запускается асинхронно через `FastAPI BackgroundTasks` в момент загрузки файла пользователем. Вся логика пайплайна лежит в `app/ingestion/`.

## 2. RBAC (Ролевая модель) и Хранение
* **ПРАВИЛО:** Доступ к документам разграничивается по ролям.
* **ПРАВИЛО:** База пользователей и их пароли/роли, а также статусы документов хранятся в реляционной БД (PostgreSQL), запущенной внутри отдельного Docker контейнера (с volume для данных).
* **ПРАВИЛО:** При загрузке файла администратор указывает массив `allowed_roles`. Этот массив должен быть сохранен в `payload` вектора в Qdrant, чтобы использовать `Pre-filtering` на этапе поиска.

## 3. Генерация Ответов (LLM)
* **ПРАВИЛО:** Мы не хостим локальную LLM прямо внутри наших Docker-контейнеров, чтобы не усложнять инфраструктуру. 
* **ПРАВИЛО:** Инференс выполняется во внешнем приложении (например, LM Studio). FastAPI общается с ним через OpenAI-совместимый клиент.

## 4. Архитектурный стиль (FastAPI)
* **ПРАВИЛО:** Zero Business Logic in Routes. В папке `app/api/` находится только логика приема запросов, Pydantic-валидация и возврат ответов. Вся бизнес-логика Retrieval и Ingestion находится в `app/services/` и `app/ingestion/`.
* **ПРАВИЛО:** Не дублировать код. Общие клиенты (Qdrant, Embeddings) выносятся либо в `app/core/`, либо в папку `shared/`.
