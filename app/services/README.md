# Business Logic & Services (`app/services`)

## Назначение
Основная бизнес-логика (Business Logic) RAG-системы. Здесь реализуются пайплайны извлечения контекста (Retrieval), переранжирования кандидатов (Reranking) и генерации итогового ответа через LLM.

## Ожидаемая структура
* `__init__.py`
* `retriever.py` — Реализация гибридного поиска (Hybrid Search) в Qdrant: Dense (косинусное сходство) + Sparse (BM25). Объединение результатов с помощью алгоритма Reciprocal Rank Fusion (RRF).
* `reranker.py` — Логика переранжирования найденных чанков с помощью Cross-Encoder (например, `bge-reranker-large`). Отбор Top-K релевантных кусков.
* `qa_chain.py` — Финальная стадия: сборка контекста из чанков, внедрение его в промпт и стриминг (или разовая генерация) ответа от LLM.

## Правила написания кода
- **Isolation:** Сервисы не должны зависеть от FastAPI объектов (например, `Request` или `Response`). Они принимают на вход чистые Pydantic-модели из `app/models` или стандартные типы Python.
- **Traceability:** Максимальное покрытие логами каждого этапа RAG (сколько чанков найдено, скор после переранжирования, время генерации ответа) для отладки метрик (Latency, Tokens).
